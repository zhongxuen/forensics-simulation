# src/features/evidence-browser

The Evidence Browser (`docs/plan/05-workspace-ui.md` §Evidence Browser), modelled on Autopsy: a tree of drives, partitions and folders, a table of file records with their MACB times, and a detail view with **Text**, **Hex**, **Metadata** and **Real-world equivalent** tabs. It is the case workspace's Evidence pane (`src/features/cases/components/evidence-pane.tsx`), which loads it on demand, so none of it is in a page's first download.

**It never reads an image itself.** It gets the workstation's engine state (which images are attached, and each write-blocker) and a `browse(path)` callback, which opens an image through `browseImage` in `src/sim/tools/forensics/browse.ts`: the same `findImage` and `openImage` the disk tools call. With a blocker on, opening the original changes nothing; with it off, the original's access times move exactly as they would for `lsfs`, the tools' warning shows, and the table draws the changed times. Everything on screen comes from the view the engine returned. If the image changes after that (a read with the blocker off, Reset machine), the drive is marked as changed and has to be opened again; the browser never quietly re-reads it. The case runner logs every open, so a saved run replays it.

- `browser-tabs.ts`: `EvidenceBrowserProps`, and `BROWSER_TABS`, the browser's views. Files is the only one; file 08 adds a Processes tab from `memory/` with one line. With one tab available, no tab bar shows.
- `model/`: the pure parts, tested without a browser. `tree.ts` builds the tree (the file records live on the drive's largest partition; the others hold nothing in the simulation) and marks stale views. `table.ts` is the table's scope (the selected folder, or the whole drive while a filter is on), sort, filters (deleted only; a time window on M, A, C, B or any), times in UTC or the drive's own zone, and reading a `datetime-local` value in that zone. `bytes.ts` is the hex dump's rows and the Text tab's text or readable runs.
- `components/`: `EvidenceBrowser`, `FilesView` (the three parts and their state), `EvidenceTree` (the ARIA tree pattern), `RecordTable` (the sortable table, one tab stop for its rows), `RecordDetail` and its tabs, `HexView` (virtualised: only the rows in view are drawn), and `ImageDetail` / `PartitionDetail`.

**Keyboard.** Tree: Up and Down move, Right opens (reading a drive the first time) or steps in, Left closes or steps out, Home and End, Enter or Space opens a drive, `p` pins a folder. Table: Up and Down move (the details follow), Home and End, Enter opens a folder or moves to a file's details, `p` pins or unpins. Pins are artefact refs (`disk:<image>:mft/<record>`) on the run's board, the same one the terminal's `pin` fills. **Show in terminal** puts `inode <path> <record>` at the prompt without running it.

**Accessibility.** The table is the accessible form of the tree: everything, a folder at a time, with real table semantics and a caption that names the keys. Deleted records are struck through and say "deleted" in words. A polite live region says what pinning and opening did.

Never import here: another feature's internals, `src/app`, or browser storage. Import the engine only through `@/sim` and `@/sim/types`.
