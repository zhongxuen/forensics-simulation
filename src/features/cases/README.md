# src/features/cases

A case, from briefing to debrief (`docs/plan/05-workspace-ui.md`). Public API in `index.ts`, with everything that reads a file or runs the generator behind `server.ts`.

- `loader/` (file 03, server-only through `server.ts`): `source.ts` reads one case file and checks everything that file alone decides — the YAML, the schema, that the story generates, and that every report question's `acceptedEvidence` still matches something. `catalog.ts` is every case in `src/content/cases`, cached in production. `spec.ts` is the one function joining the authoring schema to the generator's input, so the compiler notices if they drift. `loader/evidence.ts` is the browser side: `loadEvidence(caseId)` fetches a case's generated evidence as its own chunk.

- `run/`: the pure parts. `case-run.ts` is `caseRunReducer` (briefing → workspace → report → debrief), modelled on Hacker Simulation's `missionRunReducer`, plus `toSave`, which picks out what's kept in this browser. `evaluate.ts` is the **stub** objective evaluator (`event` and `commandRun` checks, the mission schema's names) until file 03's evaluator replaces it. `case-definition.ts` is `RunnableCase`, the runner's view of a case; file 03's loader maps a parsed case YAML onto it. `replay.ts` replays a saved command log through the terminal's `submitLine`, for tests and headless play. `use-case-run.ts` holds the reducer in React and saves after every change through `@/lib/case-storage`. `practice-case.ts` and `practice-evidence.ts` are a short case playable with workstation commands, with evidence from the builder, until file 03's fixture case and file 06's Case 1 exist. `catalog.ts` lists the cases for `/cases`. `evidence.ts` loads a case's evidence with a dynamic `import()`.
- `components/`: `CaseRunner` (the page's entry: briefing, and a lazy `case-play.tsx` chunk with everything after Start case), `CaseWorkspace` (the terminal on the left, the tabbed panes on the right; one view at a time on a narrow screen), the Evidence and Objectives panes, the empty states for panes that aren't built yet, the report placeholder, the debrief, the blocked-storage banner and the case list.
- `workspace-panes.ts`: the pane registry. **Files 09 (timeline) and 10 (case board) add one line each here** (`{ id, label, load: () => import(...) }`) and nothing else. A pane's module default-exports a component taking `WorkspacePaneProps`.

**Saving.** A save holds the command log (lines typed and Reset machine presses), pins, notes, the report draft, ticks, hint tiers and story lines played, never the engine's state. Opening a case with a save replays the log through the terminal session before the first paint. When storage is blocked or full, the case plays on and a banner says it won't be kept.

Never import here: another feature's internals, `src/app`, or `localStorage` (use `@/lib/case-storage`). Nothing in `run/` imports React except `use-case-run.ts`.
