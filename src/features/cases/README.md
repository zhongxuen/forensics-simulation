# src/features/cases

A case, from briefing to debrief (`docs/plan/05-workspace-ui.md`). Public API in `index.ts`, with everything that reads a file or runs the generator behind `server.ts`.

- `loader/` (file 03, server-only through `server.ts`): `source.ts` reads one case file and checks everything that file alone decides — the YAML, the schema, that the story generates, and that every report question's `acceptedEvidence` still matches something. `catalog.ts` is every case in `src/content/cases`, cached in production. `spec.ts` is the one function joining the authoring schema to the generator's input, so the compiler notices if they drift. `loader/evidence.ts` is the browser side: `loadEvidence(caseId)` fetches a case's generated evidence as its own chunk.

  **Headless play** lives here too, because it needs the case file and the generator. `scenario.ts` builds the analyst workstation a case is examined from: the vendored sandbox machine, plus the case's own folder (the signed letter and the handover form) and its evidence attached under `/dev/evidence`. `play.ts` runs a list of steps against it through the terminal's own `submitLine` — the same parser, engine and **tool registry** as the browser — and grades the report: a finding is `supported`, `needs-evidence` or `not-yet` (`docs/plan/00-overview.md` §4, row 7). `playthroughs.ts` reads the scripted run beside each case, `verify.ts` checks it went as written, and `transcript.ts` prints it. Because play goes through the registry, a tool added in `src/sim/tools/forensics/index.ts` is usable from a playthrough the moment it is registered.

- `run/`: the pure parts. `case-run.ts` is `caseRunReducer` (briefing → workspace → report → debrief), modelled on Hacker Simulation's `missionRunReducer`, plus `toSave`, which picks out what's kept in this browser. `evaluate.ts` is the **stub** objective evaluator (`event` and `commandRun` checks, the mission schema's names) until file 03's evaluator replaces it. `case-definition.ts` is `RunnableCase`, the runner's view of a case; file 03's loader maps a parsed case YAML onto it. `replay.ts` replays a saved command log through the terminal's `submitLine`, for tests and headless play. `use-case-run.ts` holds the reducer in React and saves after every change through `@/lib/case-storage`. `practice-case.ts` and `practice-evidence.ts` are a short case playable with workstation commands, with evidence from the builder, until file 03's fixture case and file 06's Case 1 exist. `catalog.ts` lists the cases for `/cases`. `evidence.ts` loads a case's evidence with a dynamic `import()`, one shared promise per case (the briefing warms it up), without importing the engine. `workstation.ts` attaches that evidence to the workstation (`evidenceSetup`, run again on Reset machine) and opens a drive for the Evidence Browser through the engine (`browseChange`), on the live session and in replay alike.
- `components/`: `CaseRunner` (the page's entry: briefing, and a lazy `case-play.tsx` chunk with everything after Start case), `CaseWorkspace` (the terminal on the left, the tabbed panes on the right; one view at a time on a narrow screen), the Evidence pane (the Evidence Browser from `src/features/evidence-browser`, loaded when the tab first opens, plus what else was handed over), the Objectives pane, the empty states for panes that aren't built yet, the report placeholder, the debrief, the blocked-storage banner and the case list.
- `workspace-panes.ts`: the pane registry. **Files 09 (timeline) and 10 (case board) add one line each here** (`{ id, label, load: () => import(...) }`) and nothing else. A pane's module default-exports a component taking `WorkspacePaneProps`, which includes the `workstation`: the engine's state, `browse` (the only way a pane reads a drive) and `showInTerminal`.

**Saving.** A save holds the workstation's log (lines typed, Reset machine presses, and drives opened in the Evidence Browser, because opening an original with its write-blocker off changes it), pins, notes, the report draft, ticks, hint tiers and story lines played, never the engine's state. Opening a case with a save replays the log through the terminal session before the first paint. When storage is blocked or full, the case plays on and a banner says it won't be kept.

Never import here: another feature's internals, `src/app`, or `localStorage` (use `@/lib/case-storage`). Nothing in `run/` imports React except `use-case-run.ts`.
